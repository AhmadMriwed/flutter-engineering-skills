# Versioning policy

This repository starts in development at 0.1.0. Use PATCH for backward-compatible clarifications and fixes, MINOR for additive profiles and capabilities, and MAJOR for intentionally incompatible rules or consumption contracts. During 0.x, call out all breaking changes explicitly even if a development release is approved separately. Update VERSION and CHANGELOG together once the proposed version is approved. Tagging and publishing are separate release actions.

See [Semantic Versioning](https://semver.org/) and [governance](GOVERNANCE.md).
