# Release checklist

- [ ] Review the worktree, tracked refs and any history intended for publication. Check credentials, personal metadata, private hosts, original assets, source identifiers and proprietary code. Resolve or approve the exposure of Git author/committer metadata.
- [ ] Verify redistribution rights for templates, snippets, documentation and reference-derived material. Approve the license and its copyright holder before adding a license file.
- [ ] Run the validators, Dart and Flutter analysis, and both state-assembly widget scenarios. Record SDK, platform, scope and gaps.
- [ ] Install from a clean copy and invoke from each available agent. Verify profile choice precedes scaffolding. Record actual results separately from expected discovery behavior.
- [ ] Review GitHub Actions, issue templates and private vulnerability reporting settings. Check CI when GitHub is available.
- [ ] Align VERSION and CHANGELOG and approve the final diff before committing. Approve public repository setup, push, tag and release separately.

See the [versioning policy](VERSIONING_POLICY.md) and [contributor workflow](../CONTRIBUTING.md).
