# Security policy

Report suspected credential exposure, unsafe instructions or a vulnerable dependency privately to the repository maintainer. After a GitHub repository exists, use its private vulnerability reporting channel if enabled. Avoid posting credentials, private URLs, customer records or exploit details in a public issue. Share affected versions and paths, impact and a redacted reproduction when appropriate.

Use synthetic fixtures and a disposable project for validation. If a credential has been exposed, revoke or rotate it and notify its owner before discussing any history cleanup. The maintainer reviews supported versions and coordinates disclosure.
