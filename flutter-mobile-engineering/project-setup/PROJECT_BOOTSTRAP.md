# Bootstrap a Flutter project

Complete [project decisions](PROJECT_DECISION_WORKFLOW.md) before executing the selected starter. Once approved, pin the skills revision and profiles, create the project profile, select the SDK and platforms, resolve dependencies, and configure environment, platform identity and tests.

For STATE-GETX use [the feature-first GetX starter](../architecture/profiles/feature-first/GETX_BOOTSTRAP.md). Keep larger recipes with their owning profile. Read [the profile lock](ARCHITECTURE_LOCK.md) before subsequent feature work.

For an approved STATE-CUBIT project follow the [Cubit workflow](../state-management/cubit/WORKFLOW.md) and [templates](../state-management/cubit/TEMPLATES.md). Use a Flutter Navigator route with BlocProvider.create and a GetIt factory, as demonstrated by the [reference-free fixture](../validation/PORTABILITY_TEST.md).
