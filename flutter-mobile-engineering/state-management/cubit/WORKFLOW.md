# Implement or modify a Cubit feature

1. Discover the approved project combination. For a new app use the [project decision workflow](../../project-setup/PROJECT_DECISION_WORKFLOW.md). For an existing feature read its route and lifecycle before changing dependencies or conventions.
2. Under the feature directory define outcomes and ownership. Keep simple UI state local. Place the API contract in domain/repository, adapter/model under data, and state/commands under cubit. Add an argument type only when needed. Follow [API contracts](../../core/networking/API_CONTRACTS.md). CRUD needs explicit read and save outcomes, optional delete when supported, and list reconciliation after a mutation.
3. Implement with constructor injection. Register repositories in the existing composition root and register the Cubit factory. Wrap the screen in the actual route. Only share at an enclosing flow scope with a known lifetime. Build narrow sections from state and pass values and callbacks into reusable widgets.
4. Model applied queries separately from unfinished filter edits. Normalize input; debounce only text-driven search. On filter change invalidate the old generation, reset continuation, and preserve append retry context. Use the backend continuation and deduplicate stable IDs. The REF-002 paged list was observed, but safe filter-change overlap in that source remains unverified.
5. Use a Form and local editing controllers when input need not survive the route. Map server field errors to fields. Track list and mutation status independently when both can run. Show initial loading inline in the owning region, preserve usable data during refresh, and trigger navigation/toasts through a listener or action completion.
6. Test the real provider path, loading/empty/error, retries, input, two ordered and reordered requests, close, and narrow RTL. See the [portable example](../../validation/PORTABILITY_TEST.md). When modifying an existing feature, preserve route signatures, state ownership and API contracts unless the requested change requires them.
