# Coding and naming standards

Name files in snake_case, types in UpperCamelCase and methods and fields in lowerCamelCase. Keep feature names and semantic actions recognizable throughout routes, UI and contracts. Scope changes to the owner, reuse existing primitives, and preserve behavior relied on by callers. Separate presentation, effects and external I/O through the mechanisms approved for the project. Validate at the relevant boundary and make lifecycle ownership explicit. Use [decision criteria](DECISIONS.md) and [engineering verification](../quality/ENGINEERING_QUALITY.md).
