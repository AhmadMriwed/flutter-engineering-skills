# Maintaining Flutter engineering skills

Read the [task index](flutter-mobile-engineering/SKILL_INDEX.md) and relevant profiles first. Edit the owning standard once and link to it from other profiles. Preserve rule IDs and keep architecture, reactivity and DI scopes explicit. Update impacted templates, examples, indexes, coverage and compatibility alongside changed rules.

Use [governance](docs/GOVERNANCE.md) for proposal and approval boundaries. Collect reproducible evidence, preserve reference projects, avoid importing sensitive material and document verification gaps. Keep source evidence separate from portable requirements. Update the changelog and run both [local checks](CONTRIBUTING.md). Perform Git Push only when explicitly requested.

Keep the installable skill contents self-contained and verify the reference-free example when changing profile selection, templates or compatibility.
